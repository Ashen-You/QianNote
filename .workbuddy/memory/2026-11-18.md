## 连续滚动共享画布：重写为「单一滚动权威」+ 混沌测试（v2.1.0 / build 16）

### 问题
用户报两个 bug：①滚动时频闪 + 页面被强行拽走（滚动偏移）；②跨页书写笔迹断层，要求「共用一个画布、页间无缝隙」。

### 根因（已证实）
旧实现有**两个滚动权威**：`UIScrollView` 和 `PKCanvasView` 各自维护 contentSize/contentOffset/zoomScale，每帧手工同步，永远有半帧偏差。
- 频闪：`displayScale` 通过 @Binding 每帧回写 SwiftUI @State → 整个 body（几十个 NotePageView）重建。
- 断层：`canvas.zoomScale` 与 scroll 缩放叠加 → PencilKit 二次重采样，笔迹在页内被切成两段。
（数据层当时已排除：`[INSPECT]` 确认跨页是一笔完整的 25 点笔迹。）

### 新架构（ContinuousInkCanvas.swift）
```
UIScrollView(唯一负责滚动+缩放, viewForZooming)
└─ contentView(逻辑尺寸, 被 transform 放大)
   ├─ host.view(SwiftUI 背景, 逻辑尺寸)
   └─ PKCanvasView(逻辑尺寸, zoomScale 恒为 1)
```
三条不可破的规矩：
1. 画布与背景在**同一坐标系**，都是 contentView 的直接子视图，由同一个 zoomScale 一起放大。
2. 画布 `zoomScale` 永远 1（缩放不允许有两处权威）。
3. **不往 SwiftUI 回写缩放比例**（kill 掉 displayScale 反馈环）。背景不做 scaleEffect。

### 踩到的坑（都被测试逮住）
- **UIScrollView 用 transform 放大 zoom 视图**：在带 transform 的视图上写 `frame`，UIKit 会反推 `bounds = frame/scale`，内容尺寸被悄悄缩掉（背景变小、墨迹错位）。改尺寸必须先摘 transform、写完再装回。
- **contentSize 不会因 zoomView 尺寸变化而重算**：手改 bounds 后必须显式 `scroll.contentSize = 逻辑尺寸 × scale`，否则滚不到底。
- **zoomScale 夹取**：`minimumZoomScale` 默认 1、`maximumZoomScale` 默认 1，先放开再设，且写入值要自己夹到 [fit, fit*6] 再比较，否则视图旋转后 zoomScale 停在旧 fit（会出现「低于最小缩放」并且无限 layout 循环的风险）。
- 首次 applyZoom 不能做「保持视口中心」的锚点还原，否则一打开页面顶部就被顶出视口（看起来像自己滚了一下）。
- 程序化跳页后 `isSyncing` 挡住了 didScroll，必须主动回写页码，否则底栏页码停在旧值。
- 笔落在惯性滑行中会「拉花」：`canvasViewDidBeginUsingTool` 里刹停 `isDecelerating`。

### 验证手段（模拟器无触摸注入，所以靠这几条）
- `QianNoteTests/ContinuousCanvasChaosTests.swift`：直接驱动 ContainerView/Coordinator，断言「同一逻辑点在画布坐标系与背景坐标系的屏幕位置误差 < 0.01pt」= 笔迹不可能错位/断层；5 个 seed × 300 步随机（滚动/缩放/跳页/增删页/改视口/回弹）。
- 录屏分析：launch 参数自动滚屏 → 抽帧 → 比「墨迹位移」与「纸张位移」，差值 ≤1px；亮度无突变（无频闪）。
  - 注意：拿横线做互相关会因周期性（56pt 间距）产生混叠，判据应换成「红线到最近横线距离」，应在 0–1.5px 稳定。
- 视觉：页 0/1/2/5 截图 + 2.5×/4× 缩放，红线页首标记紧贴页边界、蓝线跨页连续。

### 已知取舍
- 放大后**纸张横线会发虚**（背景是 1:1 栅格化后被 transform 拉伸；PencilKit 会按变换重绘所以墨迹仍锐利）。试过 `host.view.contentScaleFactor` 无效（像素剖面完全一致），已回退。
- 默认缩放是「适应宽度」，一屏只看到约 40% 页面高度（与此前一致，未改动）。

### 清理
移除：DebugSeed.swift、`-openSeededNote`、`-openAtPage`/`-zoomLevel`/`-logGeometry`/`-autoScroll`、`[INK]` print、DebugInspectTests.swift、EditorView 里已死的 applyFlowPinch/applyFlowPan/toggleFlowZoom/flowPanToScroll/flowViewportWidth/continuousPage/flowSwipeAccum。

### 结果
56 个单测全绿（含 9 个 InkComposer、7 个混沌）。5 轮混乱测试通过：12 页滚屏、2.5× 滚屏、60 页滚屏、缩放 4×、全量回归。版本 2.1.0 build 16。

## 2.1.1 拖动工具并入工具列表（未提交）

### 背景
iPad 上「写不了字」的根因是 `ToolStore.handMode` 这个独立布尔被持久化：停在拖动模式时滚动/缩放都正常、笔怎么画都不出墨，且无提示。

### 改法：把「拖动」变成 ToolKind 的一个 case
- `ToolKind` 新增 `case hand`；新增 `static var drawingTools: [ToolKind]`（过滤掉 hand）供工具栏遍历，避免出现两个「手」。
- 删除 `ToolStore.handMode`，改为 `var isHandTool: Bool { activeTool == .hand }`。
- 工具栏手按钮 `tools.activeTool = .hand`，点任意笔自然互斥；手按钮不再有「再点一下取消」和长按（工具没有取消态）。
- `activeTool` 持久化时**跳过 `.hand`**：拖动是临时浏览状态，不该跨启动；init 里读到 hand 也忽略，并清掉旧键 `tool.handMode`。
- 删掉 EditorView 菜单与帮助页里两处「拖动模式」Toggle（重复入口）。
- 引用点：NotePageView(isNavigating/pencilCanPan)、EditorView(isDrawingEnabled)、toolKey。

### 验证
- 编译通过；56 个单测全绿。
- 新增 `QianNoteUITests` UI 测试 target（真实触摸注入，黑盒，无测试后门），6 个用例：
  1. 手指书写落墨 + 退出重进仍在
  2. 手指拖动只滚动不留墨、能翻页
  3. 换笔继续出墨、橡皮能擦掉
  4. 边界：页顶/页底/纵向长笔画无断口
  5. 5 轮混乱（随机工具 + 随机笔画 + 随机翻页）
  6. 拖动工具与笔互斥、拖动时绝不落墨、切回笔能立刻书写 ✅ 已通过
- 断言方式：截图数墨迹像素（灰度 < 阈值），不用任何内部 API。
