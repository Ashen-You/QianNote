## 撤销/重做置灰（根因）+ 无笔手势

- 根因：`DrawingCanvas.makeUIView` 从未设置 `canvas.delegate = coordinator`。`canvasViewDrawingDidChange` 是撤销栈、
  自动保存、形状识别、虚线切分、录音笔迹打点的唯一入口，代理没接上 → 顶栏两个箭头永远置灰且无效，
  墨迹也不会落盘。已补上并加注释。
- `CanvasControllerPool.undo/redo` 改为 `undo(pageID:) -> Bool`，按页精确派发并返回是否真的撤销。
- 新增手势：两指点击撤销、三指点击重做（Notability 惯例）。实现要点：
  - 用 `TrackingCanvasView.onMultiTouchDown`（在 super.touchesBegan 之前）记下 `historyDepth` 与笔画数；
  - 识别成手势后 `truncateHistory(to:)` 丢掉误触的撤销步，只清理 <14pt 的点状笔迹（防止误删真实笔迹）；
  - EditorView 侧加触感 + 浮条提示（已撤销 / 没有可撤销的操作），设置页补手势说明。
- 验证：模拟器里用临时 selftest（`canvas.drawing = ...` 触发代理）确认 canUndo→true、undo 后笔画数归零、canRedo→true；
  临时代码已删除，未进提交。提交 `aaaf5fc`。

## 第二轮：纯手拖 + 「笔一抬左边就没了」

- 症状定位「笔起来瞬间左边部分消失」：`ShapeSnapper` 的直线分支只看首尾两点，只要 RDP 抽稀后 ≤2 个角
  就返回 [start, end]。写字的带钩/带弧笔画（亅、乚、撇）首尾一拉就成一条斜直线，看着像左边被抹掉。
  修复：直线判定加弯曲度闸门 `pathLength / chord < 1.08`，并删掉与直线互斥的 `pathLength > diagonal*1.1` 前置守卫
  （这条守卫让「笔直」的线永远进不了分支，逻辑上自相矛盾）。
  验证方式：把 ShapeSnapper 抽出来跑几何单测（/tmp 里，未入库）——直横线/抖横线→2 点，带钩→nil，抛物撇→nil，方框→5 点，圆→65 点，小笔画→nil。
- 另外两处同类保护：书写中（`isUsingTool`）不触发形状识别、也不在 `snapLastStroke` 里回填 drawing（否则会打断当前笔画）；
  `canvasViewDrawingDidChange` 改成 0.25s 合并落盘、抬笔 flush，撤销按「一笔一步」在 Begin/EndUsingTool 之间记快照。
- 纯手拖：`ToolStore.fingerDrawing` 在工具面板底部做成「书写 / 拖动」分段控件；拖动模式挂单指 UIPanGestureRecognizer
  （`allowedTouchTypes = .direct`），位移按 `fit × zoom` 换算，1× 时累积 84pt 翻页。连续滚动模式靠祖先 UIScrollView 自己滚。

## 第三轮：关掉形状识别还是截断 → 实测抓到真凶

- 排查手段：把 iPad 截图里的页面缩略图和画布逐块放大对比。缩略图（由已保存墨迹渲染）里有完整的圈注和笔迹，

## 第四轮：工具面板改成浮层（遮罩盖在页面上）

- 布局原本 `HStack { rail; palette; pageArea; pageStrip }`：面板一展开就把画布挤窄，纵向放不下时被容器直接切掉。
- 改为：rail 独占左侧，页面占满剩余宽度；面板走 `overlay(alignment: .leading)` 浮在页面之上，
  `.padding(.leading, 66)` + 卡片内 12pt 留阴影 → 卡片左边缘 78（= 12 + 58 + 8，正好贴住工具栏右侧）。
- **踩坑**：overlay 挂在 `.padding()` **之后**时，范围是整块屏幕（padding 是 frame 的一部分），
  面板从 y=0 开始布局，顶部被顶栏压住切掉。必须挂在 padding **之前**。
- 竖向溢出用 `ViewThatFits(in: .vertical) { card; ScrollView { card } }`：放得下按内容高度，放不下才可滚，
  避免以前「直接裁掉」；也避免常驻 ScrollView 铺满高度后在页面上留一条吃触摸的空档。
- 遮盖层：页面 group 上叠 `LinearGradient(black 0.14 → 0.04 → clear)`，`allowsHitTesting(false)`，
  只做层次不拦笔（Pencil 照常写）。
- 验证：临时 `-openFirst` 启动参数自动进编辑页截图（已删），面板从「钢笔」标题到「手指」说明完整可见，页面不再被挤窄。提交 2e5b6e1。

## 第六轮：换页串墨迹（下一页的笔记跑到上一页）——真凶是落盘归属页

- 症状：第 2 页写的墨迹出现在第 1 页；用户怀疑是「欢迎介绍页的内容和笔记冲突」。
- **数据取证**：模拟器容器里 Welcome 笔记两页的缩略图（t_*.png）内容完全不同，但画布上第 1 页显示的是第 2 页的图案
  → 不是欢迎页文字的问题，是画布/文件拿到了别页的 drawing。
- 根因：`DrawingCanvas.updateUIView` 换页分支顺序错了 —— 先 `coordinator.parent = self`（已是新页），
  再 `flushCurrentDrawing()`；而 flush 走 `parent.onChange`，于是**旧页还没落盘的墨迹被写进新页的文件**，
  `NoteStore.drawingCache` 同时被污染，之后每次加载/生成缩略图都带着别页内容。
  反方向同理，来回翻页就「互换」了两页。
- 修复：Coordinator 记住 `ownerSave`（这份墨迹属于哪一页的保存闭包），
  合并保存 / 抬笔 flush / `dismantleUIView` / `applyProgrammatic` 一律走 `saveToOwner`；
  换页顺序 = 先按旧页 flush → 再改 owner → 再 `bind(controller:to:)` 绑新页撤销栈。
  同时 `bind` 会解绑旧页 controller 的 `canvas`/`onDrawingRestored`（否则旧页撤销会画到当前页）。
- **A/B 实测**（临时 `-pagetest` 启动参数，已删）：页 1 写 2 笔后立刻翻页、页 2 写 5 笔再翻回，
  · 旧逻辑：p1=5 / p2=2（互相串）  · 新逻辑：p1=2 / p2=5（各自独立）。
- 注意：已被污染的旧文件是「整页覆盖」，不是合并，无法自动还原；只能人工清理。
- 提交：7f53b5d。

## 第七轮：文字功能重做（「删不了」）

- 取证：读模拟器容器 index.json，发现**第 2 页有 9 个空文字框，x=756~765（页宽 768）**。
  旧 `addTextBox` 里 `width = min(320, pageWidth - x - 20)`，靠右边缘点按算出 **-8**：
  负宽度视图连 contentShape 都是空的 → 点不到、也渲染不出右上角那颗 ×，等于永久删不掉。这就是「删不了」的根因。

- 改法（8be4d04）：
  · 宽度最小 140、x 夹在 `pageWidth-156` 内，杜绝负宽度；
  · **就地编辑**：点框/点空白处直接换 `TextField(axis: .vertical)`，删掉整个 `TextBoxEditor` sheet，
    键盘 `ToolbarItemGroup(placement: .keyboard)` 放 A−/A+/删除/完成；框高随内容自适应（旧版固定 80 截断）；
  · 空内容提交 → 直接删框；`NoteStore.load()` 加 `sanitizeTextBoxes()` 清历史空框 + 负宽度框；
  · 手势：× 作为 ZStack 兄弟节点，不吃父级 onTapGesture；编辑中一律不挂 tap/drag（否则抢走光标定位与拖选）；
  · 提交时从 `store.note(id:)` 取框，而不是 body 里的 `page` 值 —— 新建框后视图换了新 note，用旧值找不到新框（这个坑让第一版测试「写完没保存」）。
- 验证（临时 `-texttest` 文件日志，已清理）：add→5、commit 后文本 "第一行\n第二行"、清空→4、右边缘 x=760 创建→夹到 612/w=140、删除→4。
  截图确认两行文字、虚线框、红色 × 位于框内右上且不压字。

## 第八轮：缩略图刷新提速（「感觉缩略图状态刷新很慢」）

- 根因三条叠加：
  1. `scheduleThumbnail` 是**消抖**：每次落盘都把定时器重置到 1.2 秒后 → 一直在写就永远不刷新，抬笔后还要再等 1.2 秒 + 一次整页渲染；
  2. 缩略图渲染和落盘共用一条**串行** `ioQueue`，书写时每 0.25 秒的保存编码排在它前面；
  3. 取图（`ensureThumbnail`）在 SwiftUI `.task` 里同步 `Data(contentsOf:)` + `UIImage(data:)`，一屏十几张卡片 = 十几次主线程 IO + 延迟解码。
- 改法（3e0c78f）：消抖 → **节流**（距上次渲染 >0.9s 就 0.15s 后补一版，书写期间每 0.9s 一版）；
  独立 `thumbnailQueue`；`PageRenderer.renderBase` 缓存「纸张/PDF」底稿、`renderPage(baseLayer:)` 贴图；
  墨迹按 `520/页宽` 栅格化（原来 1 倍画满页再缩小）；`thumbnail()` 改 async；版本号改按页 `thumbnailVersions` 字典。
- 实测（临时 `-thumbtest`，Debug 模拟器，200 笔）：冷渲染 990ms（base miss）→ 命中 23–46ms；
  连续书写 3 秒内 render 于 2.3/3.26/4.2/5.14s 各一次（≈0.9–1.0s 一版）。测完删除钩子，重装模拟器还原干净数据。
- 经验：节流器不要「有请求就 cancel 重排」，否则连续输入会把刷新无限推迟；要按「距上次执行的时间」算延迟，
  并用「代计数」在渲染结束时检测是否又脏了（同 `saveDrawing` 的写法）。

## 第二十一轮：撤销按钮置灰 → 接入系统 UndoManager（三指/摇一摇/⌘Z）
- 用户截图红框标出撤销/重做按钮灰色，选定方案 B：接入系统 undoManager，让 iPad 三指滑动/摇一摇/外接键盘 ⌘Z 也能撤销。
- 根因澄清：截图里灰掉的是 macOS 模拟器顶部「Edit 菜单」的系统级 Undo/Redo，App 之前完全没接系统 undoManager（搜不到任何 undoManager 调用），所以永远灰——真机无此菜单栏。工具栏箭头按钮由 `controllers.canUndo/canRedo` 驱动，画完抬笔后正常亮。
- 实现（QianNote/Views/DrawingCanvas.swift）：
  1. `CanvasController` 从纯 Swift 类改 `NSObject, ObservableObject`，加 `weak var systemUndoManager: UndoManager?`。
  2. `record` 末尾 `registerSystemUndo()`：每次落笔向系统 undoManager 追加一个「撤销」动作（block 式 `registerUndo(withTarget:handler:)`，handler 调 `undoFromSystem`）。
  3. `undo()/redo()` 统一走系统入口：`if let um = systemUndoManager, um.canUndo { um.undo() } else { rawUndo() }`，把三指/⌘Z/工具栏/手势全收敛到一条路径。
  4. 自平衡反向注册：`undoFromSystem` 里 `registerUndo(... redoFromSystem)`（此刻 isUndoing 为真，落到 redo 栈）+ `rawUndo()`；`redoFromSystem` 对称。
  5. `rebuildSystemUndo()`：切页/截断历史时按自研栈深度重建系统动作。关键坑——**UndoManager 会把同一 runloop 事件内对同一 target 的多次 registerUndo 折叠成一层**，所以每层放到独立 `DispatchQueue.main.async` 里注册。
  6. `CanvasControllerPool.activate` 里先 `controller(for:)` 确保新页撤销栈存在再绑定；`bindSystemUndo` 先 `removeAllActions()` 全局清空（旧页动作挂旧页 controller，`withTarget:` 清不掉）再 `rebuildSystemUndo`。
  7. EditorView 加 `@Environment(\.undoManager)`，onAppear 里 `controllers.systemUndoManager = undoManager`。

## 第二十二轮：修复连续滚动两页之间瞬移
- 症状：连续滚动时，滚到两页中间会「马上瞬移」——被强行拽到某一页中心。
- 根因：`continuousArea` 的 `.onAppear` 里写 `if pageIndex != index { pageIndex = index }`。LazyVStack 惰性加载时，页面刚进入视口边缘（还没滚到位）就触发 onAppear，把 pageIndex 改成该页，进而触发 `.onChange(of: pageIndex)` → `proxy.scrollTo(.center)`，把视图用动画拽到页中心。滚到两页之间时下一页 onAppear 立即触发 → 瞬移。
- 修复（QianNote/Views/EditorView.swift，仅改 EditorView）：
  1. 新增 `@State continuousPage: Int?`，用 ScrollView 的 `.scrollPosition(id: $continuousPage)`（iOS 17+ 原生）拿到「最接近视口顶部锚点的页」作为实时滚动位置。
  2. 删掉 onAppear 里的 `pageIndex = index`，只保留 `controllers.activate(page.id)`。
  3. `.onChange(of: continuousPage)`：用户手指滚动到位后把 pageIndex 同步过去（纯被动，不 scrollTo）。
  4. `.onChange(of: pageIndex)` 加双重防回环：`guard !isProgrammaticScroll` + `if continuousPage == newValue { return }`——滚动同步改的 pageIndex 不再反向触发 scrollTo。
  5. ScrollView `.onAppear` 首次进入定位：从缩略图/历史恢复到非第一页时 scrollPosition 初始 nil，主动 `proxy.scrollTo(pageIndex, anchor: .top)`（无动画）跳一次。
- 状态流验证（脑内推演 + 编译 + 20 单测全绿）：
  - 用户滚动跨页 → continuousPage 变 → 同步 pageIndex → onChange(pageIndex) 因 continuousPage==newValue 短路，不 scrollTo（无回环无瞬移）。
  - 程序跳页 → pageIndex 变 → isProgrammaticScroll 置位 scrollTo(.center) → 动画中 continuousPage 变但被 flag 挡住不覆盖。
- 备注：scrollPosition 锚点默认 .top；多页连续滚动里「哪页顶部最接近视口顶部」即当前页，跨边界才切换，无瞬移。

## 第三十轮：连续滚动缩放「画布没放大、内容被固定视口裁剪」（根因终于找到）
- 用户反馈：放大后画布大小没跟着放大，窗口被固定，相当于把页面做了裁剪。
- **真根因（关键，之前多轮都绕错了）**：`continuousArea` 的 GeometryReader 初始布局阶段 `geo.size.width=0`，导致 `fit=0.0013`、`renderedWidth=2.5` 这些错误值传进 LazyVStack 里的 flowPage；且 LazyVStack 惰性缓存，flowPage 拿到 0 值后不再重新求值。所以 scaleEffect 用 `fit*zoom=0.003` 把页面缩到 2.5pt，看起来「画布没放大/空白/纸面 885px」。之前诊断 print 确认：flowPage 只被调用一次且 fit=0.0013，而 continuousArea 外层 fit=1.5625。
- 修复方案：
  1. 新增 `@State flowViewportWidth`，用 `.onGeometryChange(for: CGFloat.self) { $0.size.width }` 监听真实视口宽（iOS 17 API），避免 GeometryReader 初始 0 值。
  2. `fit` 用 `flowViewportWidth`（稳定非 0）计算，首次 0 时退回 geo.size.width 兜底。
  3. ScrollView 从 `.vertical` 改成 `[.horizontal, .vertical]` 双向滚动，横向滚动范围由内容尺寸（renderedWidth 随 zoom 放大）天然决定——放大后画布跟着变大、横向可滚动，不再手写 `offset(pan)` 平移。
  4. flowPage 缩放链保持 `.frame(pageWidth,pageHeight).scaleEffect(fit*zoom, anchor:.center).frame(renderedWidth,renderedHeight).clipped()`（与单页 pageArea 一致，.center 锚点）。
  5. 删掉 applyFlowPinch/applyFlowPan/toggleFlowZoom 里的 pan 计算和 clampedFlowPan（横向滚动交给双向 ScrollView 原生接管）。
- 验证：zoom=1 页面居中正常、zoom=2.5 纸面正确放大（横线间距变大）、内容横向溢出可滚动（不再是「画布没放大被裁死」）。20 单测全绿。**未发版**（用户还在持续迭代这个缩放）。
